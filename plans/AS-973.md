# Plan: CI/CD for LibreClinica

## Decisions

- **Registry:** GitHub Container Registry (GHCR) at `ghcr.io/mutexio/libreclinica`, public, authenticated with the built-in `GITHUB_TOKEN` — no Docker Hub secrets needed.
- **Platforms:** multi-arch `linux/amd64` + `linux/arm64`.
- **Triggers:** push to `lc-develop`, all tags, manual dispatch (`workflow_dispatch`).
- **Tags:** branch name, git tag name, and `latest` on the default branch.
- **Scope:** mirror the workflow/Makefile from `../docker-rocketchat-arm64`, adapted for this repo.

## 1. Add `.github/workflows/docker-publish.yml` (new)

Based on `../docker-rocketchat-arm64/.github/workflows/docker-publish.yml`:

- `on`: `workflow_dispatch`, `push: branches: [lc-develop], tags: ['*']`.
- `env`: `REGISTRY: ghcr.io`, `IMAGE_NAME: mutexio/libreclinica` (hardcoded lowercase — GHCR rejects uppercase; `${{ github.repository }}` would resolve to `mutexio/LibreClinica`).
- `jobs.build.runs-on: ubuntu-latest`, permissions `contents: read`, `packages: write`, `id-token: write`.
- Steps: `actions/checkout@v4` -> `docker/setup-qemu-action@v3` (arm64 emulation) -> `docker/setup-buildx-action@v3` -> `docker/login-action@v3` (`username: ${{ github.actor }}`, `password: ${{ secrets.GITHUB_TOKEN }}`) -> `docker/metadata-action@v5` -> `docker/build-push-action@v6`.
- Metadata tags:
  - `type=ref,event=tag`
  - `type=raw,value=latest,enable={{is_default_branch}}`
  - `type=raw,value={{branch}},enable=${{ github.ref_type == 'branch' }}` (avoids an empty tag on tag pushes — a flaw in the reference workflow)
- Build step: `context: .`, `platforms: linux/amd64,linux/arm64`, `push: true`, `tags`/`labels` from metadata, plus `cache-from: type=gha` / `cache-to: type=gha,mode=max` to reuse the cache mounts in `Dockerfile:9-15`.

## 2. Add `Makefile` (new)

Adapted from the reference Makefile:

- Variables: `SHELL`, `REGISTRY ?= ghcr.io`, `IMAGE_NAME ?= mutexio/libreclinica`, `DEFAULT_BRANCH ?= lc-develop`, `BRANCH_NAME` from git, `PLATFORMS ?= linux/amd64,linux/arm64`, `PUSH ?= true`.
- `ci` target builds both platforms with `--push` (requires `docker login ghcr.io` first); tags the branch name and `latest` when on `lc-develop`.
- For `PUSH=false`, build a **single native platform** with `--load` (buildx cannot `--load` a multi-platform image) — document this in the Makefile help/README.

## 4. One-time setup (manual, outside repo)

- After the first successful push, open the GHCR package -> Package settings -> **Change visibility to Public** (and connect it to the `mutexio/LibreClinica` repository).
- Confirm repo Actions settings allow read/write `GITHUB_TOKEN` so `packages: write` takes effect.

## 5. Verification

- Trigger via `workflow_dispatch` first; confirm the build passes. It runs `mvn package` from `Dockerfile:18`, including tests, once per arch under QEMU — expect a slow first run.
- `docker buildx imagetools inspect ghcr.io/mutexio/libreclinica:latest` to confirm both amd64 and arm64 manifests; pull smoke-test on available architectures.
- Verify tags: branch `lc-develop`, `latest`, and a version tag (e.g. `v1.4.0rc1`) from a tag push.
- Run `make ci PUSH=false` locally (native platform) and `docker compose build` to confirm the dev flow is unaffected.

## Notes / risks

- Keep `compose.yaml:3` as `build: .` for the dev `develop.watch` flow; optionally add an `image:` key so users can pull the published image instead.
- `tomcat:9-jdk11` (`Dockerfile:22`) and `maven:3-eclipse-temurin-8` (`Dockerfile:1`) both publish arm64 variants; no Dockerfile changes expected.
- QEMU emulation makes arm64 Maven builds substantially slower. If that becomes a problem, a later optimization is native-runner matrix builds plus a manifest merge step.
